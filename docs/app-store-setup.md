# Apple App Store Submission Guide

---

## Step 1 — Apple Developer Account & Certificates

### Prerequisites
- Active **Apple Developer Program** membership ($99/year): https://developer.apple.com/programs/ enroll/
- Your Mac with Xcode installed (latest stable version)

### Create Signing Assets in Xcode

1. Open `ios/Runner.xcworkspace` in Xcode
2. Select the **Runner** target → **Signing & Capabilities** tab
3. Check **"Automatically manage signing"**
4. Under **Bundle Identifier**, verify it says `com.pvjio.mamadera`
5. Select your Team (Apple Developer account) from the dropdown
6. Xcode will automatically create the provisioning profile

Xcode should show ✅ next to all items. If not, click the fix button that appears.

---

## Step 2 — Create App in App Store Connect

1. Go to **https://appstoreconnect.apple.com** → **My Apps** → **+ New App**
2. Fill in:
   - **Platform**: iPhone (or iPhone + iPad)
   - **Name**: `Mamadera` (must be unique — try "Mamadera Baby Tracker" if taken)
   - **Primary Language**: French (FR) — you can add EN & ES later
   - **Bundle ID**: `com.pvjio.mamadera` (match exactly)
   - **SKU Name**: `mamadera-001` (internal reference, not visible to users)
3. Click **Create**

## Step 3 — Build & Upload

### Option A: Xcode Cloud (the production route — since v1.1.0)

The app is archived, signed (auto-managed signing) and uploaded by **Xcode Cloud** —
no local machine involved. Any push to `main` triggers a build automatically
(Apple trigger: any file change on the main branch). The first green archive
landed 2026-09-20 after the hook move below.

**Why a post-clone script exists:** iOS plugins are integrated via Swift Package
Manager through the LOCAL package
`ios/Flutter/ephemeral/Packages/FlutterGeneratedPluginSwiftPackage`, which is
**generated by the Flutter tool and gitignored** — a bare Xcode Cloud clone cannot
resolve it and the archive dies in ~30 s with `Could not resolve package
dependencies`. The hook (`ios/ci_scripts/ci_post_clone.sh`) installs the pinned
Flutter SDK and runs `flutter build ios --config-only` to generate the package.
There is no Podfile-based flow in this project.

**Location convention (learned the hard way, 2026-09-20):** Xcode Cloud only
auto-detects hooks in a `ci_scripts/` directory **next to the Xcode
project/workspace** — here `ios/ci_scripts/`, beside `ios/Runner.xcworkspace`.
A `ci_scripts/` at the repo root is silently ignored (log: `Post-Clone script
not found at ci_scripts/ci_post_clone.sh` — builds 3–5). Do not move it.

### Option B: Local Xcode archive (fallback)

```bash
# From project root — generate the SPM package first, then archive in Xcode
flutter build ios --config-only
```

1. Open `ios/Runner.xcworkspace` in Xcode, select a device target
2. **Product → Archive**
3. Organizer → **Distribute App** → **App Store Connect** → Upload
   (auto-managed signing, team CQZH3JBXLD)

## Step 7 — Privacy & Ratings

### Privacy Policy URL

Host your privacy policy publicly. Since mamadera is open source, use this GitHub raw URL:

```
https://raw.githubusercontent.com/pierou/mamadera/main/.github/PRIVACY.md
```

Or host it on a simple static page (GitHub Pages, Netlify, etc.) for better formatting.

### Age Rating Questionnaire

In **App Store Connect** → **App Review** → scroll to age rating:

Answer honestly. For mamadera you'll likely get rated **4+**. The questionnaire asks about:
- Realistic violence — None
- Cartoon/fantasy violence — None  
- Alcohol/tobacco/drugs — None
- Sexual content — None (mention breastfeeding is non-sexual)
- Mature/suggestive themes — None
- Horror/frightening content — None
- Profanity — None
- Gambling — None
- Players interact online — No
- Invites users to share info — Yes (if you have a feedback/contact feature)
- Contains user content — Yes (baby tracking data is user-generated)

## Step 8 — Encryption Declaration

Because we set `ITSAppUsesNonExemptEncryption = true` in Info.plist (the app ships its own AES-256-GCM implementation via the `encrypt` package rather than calling Apple's crypto APIs), Apple will not show the per-submission encryption questionnaire. You must instead keep export compliance documentation on file (EAR self-classification report for everyday/mass-market encryption) — no per-build paperwork in App Store Connect.

## Step 9 — Submit for Review

1. In **App Store Connect** → **App Review** section:
   - Fill in demo account (if applicable) — select "This app does not require a demo account"
   - Upload screenshots for review
2. Click **"Submit for Review"** on the right sidebar

### Timeline

- First-time submission: ~1–3 business days (may take longer if they request changes)
- Subsequent updates: ~24–48 hours typically
