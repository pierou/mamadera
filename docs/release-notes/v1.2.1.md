# 🍼 Mamadera v1.2.1 — Release Notes

**The unit is a column, not an inference.** v1.2.1 makes the meaning of every
number in `tracking_events` explicit — a `unit` column lands (schema v12),
breastfeeding is entered in minutes or ml at the parent's choice, and the
history timeline unifies care events with growth measurements in one view.

- **App version** `1.2.1`, **store build** `1.2.1+11` — the rc builds shared
  `+10` on the internal track; the bump to `+11` happened at the stable pass,
  the same shape as v1.2.0 (Play rejects the same versionCode on two tracks).
- **Drift schema v11 → v12** — one additive column: `tracking_events.unit
  TEXT NULL`, no re-key. The backfill names the unit the user was shown, never
  invents one: `miam/natural` and `miam/artificial` → `ml` (the column
  default), `miam/solid` → `g`, `dodo` → `min`, `caca`/`sante` → `NULL`
  (quantity is NULL there).
- **Backup export format v2 → v3** — `unit` rides on the event rows; the
  importer accepts 2 and 3 and refuses anything newer; a format-2 feeding row
  backfills to `ml`, never `min`.

## ✨ New features

- **Unified history timeline** — weight, height and temperature appear in
  History alongside feedings, sleep, diapers and health events, sorted by
  timestamp, each row rendering its unit from its own `unit` column. The merge
  is read-only over the two tables: edit and delete are addressed to the table
  that owns the row, and measurements are never duplicated into
  `tracking_events` — where `quantity` is plaintext at rest, against
  encrypted-at-rest values in `measurements`. A failed decrypt renders a
  dedicated message, never an invented number.
- **Edit or delete a measurement from history** — the edit sheet opens on the
  existing value; a correction or deletion refreshes the home screen's latest
  value immediately.

## 🛠 Improvements

- **Breastfeeding in minutes or ml (B1)** — `natural` is the only feeding
  subtype with a unit toggle: minutes for a feed at the breast, ml for
  expressed milk, chosen per entry. New `natural` entries default to minutes;
  `artificial` stays `ml`, `solid` stays `g`, `dodo` stays `min`. The quantity
  resets to zero on every unit change, announced with a visible message —
  20 ml is not 20 minutes.
- **Out-of-range input is no longer swallowed (B5, both paths)** — the
  measurement sheet was wired earlier; the feeding dialog lands with B1's
  toggle, same file, as the backlog asked: the number stays on screen, the
  expected range is shown, and Save stays disabled until the value is back in
  range. Never a silent clamp.
- **One slider per entry form** — the coarse/fine slider pair (B2) shipped in
  rc.1 was reverted before stable: a control whose purpose has to be explained
  is not a control. The single full-range slider keeps the fine step; the
  ±steppers and the keyboard field set the exact value.
- **The entry sheet shows the last measurement directly** — no more
  « Dernière : » label; the slider and the ±steppers start from the last
  measurement of that kind, not from the type default.

## 🐛 Fixes

- Missing minutes in English dates ("07:PM") now display.
- Dropped the doubled unit on the growth trajectory ("6.18 kg g").
- English dates in history no longer overflow on small screens (date and time
  on two lines).
- Sleep entries in history show the duration once, without the duplicated
  quantity (the display half of B13 — the model still writes both columns,
  deferred).
- Decimal separator in quantity fields follows the chosen language.
- The home screen's latest value refreshes after saving a measurement, and
  after a correction or deletion made in history.
- Save / Delete buttons no longer overflow the measurement edit sheet on small
  screens.
- Consistent out-of-range message in the edit sheet ("between 200 and 20000
  g", not "200.0").

## 🔐 Privacy

No new dependency, no network, no telemetry. The backfill is this release's
privacy-critical decision and it follows B1's rule — *name the unit the user
was shown, never invent one*: a pre-1.2.1 `natural` row of `20` displayed as
"20 ml", so it backfills to `'ml'` and stays `'ml'`. Accepted consequence:
`natural` rows now carry two units across time, distinguished only by `unit`;
every aggregate must filter on it (verified before shipping: nothing sums
feeding volume today).

### Known behaviour on upgrade (by design, recorded)

- Existing `natural` rows are `'ml'` after the upgrade (what the user was
  shown); entries made from 1.2.1 on default to `'min'` with the toggle. Both
  units coexist under the same subtype — every read path renders from `unit`.
- Sleep minutes are still written into both `quantity` and `duration` (B13's
  model half, deferred): the timeline shows `Durée` only, the storage debt
  stays until its own reviewed change.
