Why flutter drive instead of touch navigation:
  The Pixel_10_Pro AVD accumulated 11 phantom virtio_input_multi_touch devices
  (event1..event11; a healthy emulator has one) after repeated kill/relaunch
  cycles. `adb shell input tap x y` routed taps to arbitrary devices, so the
  same coordinate opened different elements on repeated attempts (Menu tab
  tap -> diaper sheet / care-type sheet / Growth), and state dumps flapped
  between Growth / shell / launcher. Keyevents (BACK/HOME) still worked. The
  capture was therefore done with widget-level navigation — no touch:
    pump app (seeded in-memory DB)
    -> tap TestKeys.menuTab
    -> scroll "Choose which reminders to show" into view, tap tile
    -> scroll "System notifications" section into view
    -> binding.takeScreenshot
  This exercises the exact same route (/reminder-settings) and layout as a
  user tap; only the input path differs.

Screen state (mirrors the opted-in Small_Phone state, evidence 09-11):
  Seeded fixture baby Léa (87 days), app_settings rows
    notifications_opt_in = '1'
    notification_time_of_day = '09:30'
  so the System notifications section renders with the opt-in switch ON and
  the Notification time row enabled at 9:30 AM.
