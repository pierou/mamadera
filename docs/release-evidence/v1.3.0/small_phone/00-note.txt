## 1. Migration path, on a device that had old data  (gate item 1 — PASSED)

Executed in this order:

1. `pm clear` → install **v1.2.1+11** (`/tmp/mam121` worktree at tag v1.2.1) → accept privacy
   screen → Menu → *Ajouter un bébé* → "Nora".

   3 min) and 1 × Sommeil (60 min).

   `dodo||60.0|min`).
6. History tab shows all of it: 2 × "Lait Maternel — Quantité : 3 min / 5 min", "Durée: 60 min"

7. Add one measurement on the new build (Poids 3,51 kg) → `measurements` = 1 → home tile reads

The v12 → v13 migration was therefore executed on a database that had v12 rows, which a fresh

## 5. New finding — the baby age is hardcoded English

Menu → the baby card reads **« Nora — 0 days old »** in the French UI (visible in 22, and in the
`content-desc` dump). `lib/features/menu/presentation/widgets/baby_profile_section.dart:491-504`
builds it with string literals ('$days ${days == 1 ? 'day' : 'days'} old'), while
`daysOld`/`monthsOld`/`yearsOld` exist in all three ARBs (`app_fr.arb:439` = "jours") and are
referenced by **nothing** in `lib/`. The same six lines also compute months as
`now.month - birthDate.month`, which ignores the day of month (a baby born 31 Jan reads as
2 months old on 1 Mar). Tracked as B18.

Also seen and ruled out: the home tiles show no "+N" pill despite 3 events today — identical on
v1.2.1 and v1.3.0 (screenshots 25 vs 22), so it is not a 1.3.0 regression.

## 7. Tooling — `flutter drive` needs `--verbose` here, that is all

Earlier today `flutter drive` and `flutter test integration_test -d emulator-5554` looked hung:
0 bytes of output, 0 % CPU, holding `~/flutter/bin/cache/lockfile`, and every later flutter
command queued behind it (even `flutter devices` printed nothing for 45 s). Orphaned
`flutter_tools` processes from those stalls had to be killed twice.

**It was not hung — it is silent.** The same command with `--verbose` completed the whole fr
capture in ~90 s (8 frames, driver saved them, `verify_android.py` passed). Reproduced twice with
stdout redirected to a file, so: on this Mac, on Flutter 3.44.8, `flutter drive` writes nothing and
makes no progress signal without `--verbose`. Every v1.3.0 Play frame was therefore recaptured via
a one-line shim (`/tmp/flshim/flutter` = real flutter + `--verbose`) in front of `PATH`, running
`store/v1.3.0/capture.sh` unchanged on `Pixel_10_Pro` (emulator-5556, 1280×2856):

    fr ✓ es ✓ en ✓  →  8/8 per locale at 1280x2856, locale-prefixed, PACKAGE OK

Only `asc/*` (App Store, simulator pipeline) stays empty — the pre-existing WARN, needs the
iPhone 17 simulator run.

## 8. The App Store frames — two defects, and the campaign that fixed them

`store/v1.3.0/check.py` had been printing `WARN asc/<locale>/<size> — empty` and the
`screenshots/ios/asc/` set on disk dated from 21 Oct. Recapturing them exposed two real defects,
both silent, both now fixed:

**a) The iOS driver had not compiled since `9420097` (2026-10-18).** `test_driver/asc_screenshots.dart`
grew `import 'dart:ui'` + `lookupAppLocalizations(...)`, but a driver script is compiled by plain
`dart` on the host, where `dart:ui` does not exist. The CFE died in its FFI use-site transformer
(`type 'InvalidType' is not a subtype of type 'FunctionType' in type cast`) before the app even
launched. Replaced with the per-locale const maps this file already uses for the back-tooltip, for
exactly this reason — its own comment says "the driver cannot reach that delegate".

**b) `--dart-define` never reached the driver.** It is handed to the target app, not to the driver
process. So `_localeCode` stayed at its default `fr` on every `es`/`en` run: the app rendered
Spanish, the driver looked for « Annuler », `scrollIntoView` timed out two frames in, and `raw/`
ended up holding one Spanish frame and five French ones — which `postprocess.sh` then resized,
renamed and reported as "ready to upload". Verified: `es-menu.png` and `en-menu.png` were byte
identical to `fr-menu.png` (md5 `7dd766f2`), i.e. the App Store sets had been French under Spanish
and English filenames. The driver now reads `APP_LOCALE` from the environment as well and throws if
the two channels disagree.

`screenshots/ios/asc/campaign_asc.sh` (new) is the interleaved loop the pipeline needed:
drive → verify **14/14** raws refreshed → postprocess → copy with the locale prefix, per locale,
then a cross-locale md5 check that fails loudly if two locales are the same pixels. `check.py` only
verifies `asc/fr`, so nothing in the old pipeline could have noticed (b). Result: fr ✓ es ✓ en ✓,
28 files each (7 screens × 4 sizes), "all locale sets are distinct", `PACKAGE OK` with no ASC WARN.
Spot-checked at pixel level: `es-menu.png` now reads « Menú / Bebés / Idioma / Tema / Inicio ».

B18 is visible in these artefacts too — « Léa — 3 months old » in a Spanish screenshot, in every
locale's menu frame, at all four sizes. That is 12 Play/ASC uploadables carrying an untranslated
string, which raises its priority for v1.3.1.
