## 1. CI — verdict: A− (strongest part of the repo)

### What is good (do not regress these)

- **Comments are the documentation.** Every workaround cites the GitHub run that birthed it
  (gitleaks clone-topology 35508398140, VM-service stall 36993590980 / 7-of-8 cron runs, cmake
  "Premature EOF" 37056936839, iOS zip path that vanished artifacts since v1.0.0, PEP 668 lizard).
  Removing a step without reading its comment is the failure mode the design guards against.
- **`make gate` mirrors CI** (commit `512c2f4`, 2026-10-19). The drift was found in *both*
  directions (version-sync CI-only, store-check local-only) and fixed with a mirror target.
- **Honest integration tiering.** Self-hosted Mac = real gate (~3 min); no-KVM ubuntu leg demoted
  to `workflow_dispatch` fallback with two-stage watchdog (25 min / 50 min) + one fresh-boot retry;
  rationale and run evidence in the comments.
- **Security job:** Trivy pinned `v0.36.0` blocking HIGH/CRITICAL, Semgrep blocking, Gitleaks
  pinned `8.24.3` full-history (`fetch-depth: 0`), `persist-credentials: false` everywhere,
  least-privilege `permissions` (release job alone gets `contents: write`).
- **Ratchets, not cliffs:** architecture baseline that may only go down (`scripts/check_architecture.py`),
  complexity budget cap 3 with a `Fun Cnt ≥ 400` guard against a vacuous green, coverage ≥ 80.
- **Builds:** signed Android only on `v*` tags (keystore never touched on PRs); idempotent release
  job (`gh release view` → `--clobber`); `if-no-files-found: error` on the iOS artifact.

### P1 — fix before the next release

- **P1-1 · Required checks may not be enforced (REPORTED-NOT-VERIFIED).**
  `ci.yml` `integration-tests-local` comment: *"nothing merges on required checks anyway — there
  are none."* If branch protection on `main`/`develop` does not **require** `lint-test` +
  `integration-tests-local` (at minimum for develop → main), the entire pipeline is honor-system —
  a PR can merge red. *Check:* GitHub → Settings → Branches → branch protection rules. This single
  item can invalidate all the rest of the pipeline.
- **P1-2 · F-Droid channel is four releases behind.**
  `docs/fdroiddata/com.pvjio.mamadera.yml` still says `Version: 1.0.1`; 1.1.0, 1.1.1, 1.2.0,
  1.2.1 were never submitted, and F-Droid CI enrollment (`.f-droid/CI.yml` + `CIUrl`) is pending.
  The target audience of `PLAN-francophone-neonatal.md` is exactly the F-Droid / Play-free
  population. `AutoUpdateMode: Version v\d+\.\d+\.\d+` with `UpdateCheckMode: Tags` is already
  set, so after the catch-up PR every future release is a two-line metadata bump (Version line +
  one `Builds:` block; versionCodes: 1.1.0 → 9, 1.1.1 → 8? — **re-derive from
  `docs/release-notes/` + pubspec history, do not guess the codes**).

### P2 — fix soon

- **P2-1 · Coverage doc/gate mismatch.** AGENTS.md promises "≥ 80 % for `domain/` and `data/`
  layers"; CI's "Check Coverage Threshold" and `make check-coverage` enforce **whole cleaned tree**
  ≥ 80 % (4992/5642 = 88.5 % at the 2026-10-19 audit). Per-layer is the stricter, more meaningful
  bar for this architecture; whole-tree can be inflated by presentation tests. Make the doc and the
  gate say the same sentence (either enforce per-layer in CI or rewrite AGENTS.md).
- **P2-2 · Dart dependencies have no vulnerability signal.** Trivy skips `pubspec.lock` (justified:
  poor pub support) and there is no `dependabot.yml`. The app's own dep channel is on manual
  review only. For a privacy-mandated app: add a scheduled `dart pub outdated` + pub-package CVE
  check (Dependabot supports `pub` since 2023, or a cron step).
- **P2-3 · `macos-14` is in GitHub's deprecation window** (REPORTED-NOT-VERIFIED — check current
  runner availability announcements before acting). It is the only per-PR iOS compile signal; plan
  the move to macos-15/26 rather than discovering it as a red build.
- **P2-4 · Self-hosted Mac is a single point of failure** for the real integration gate and the
  daily cron. Mac offline → silent world, noticed only when a PR merges stale. Add a cheap
  heartbeat: the cron uploads a ping artifact, or a liveness check that pages on two missed runs.

### P3 — notes

- **P3-1 · Android Gradle breakage only surfaces at tag time** (build-android is tag-only).
  Accepted trade-off: `lint-test` + the local gate cover most of it.
- **P3-2 · iOS release ends at an unsigned `Runner.app` zip** in the GitHub release; the ASC
  archive/upload is manual. Fine for a solo maintainer — just know the asymmetry with Android.
- **P3-3 · No artifact retention policy** set (default 90 days). Fine as-is.

## 2. Branching model — verdict: B+ (clean execution, more machinery than a solo repo needs)

- The v1.2.1 cycle (snapshot §0) is **well executed**: no cherry-pick hell, main only ever moves
  on release, rc tags on the release branch, remote release branch deleted after merge.
- **The isolation was illusory.** The version-bump commit (`9205534`) flowed back into develop via
  #41, so develop carries `1.2.1+11` today. The release branch protected nothing that did not
  immediately re-enter develop.
- **Simplification candidate (owner decision, not a bug):** for a one-maintainer repo, the
  equivalent with less machinery is *no release branch* — tag `v1.2.2-rc.N` directly on develop,
  fix on develop, re-tag, tag stable, merge develop → main. Identical rc train, three fewer
  branch merges per release. Keep the release branch only if a *frozen* branch becomes useful
  (parallel trains, hotfixes on shipped versions) — it does not yet.
- **The v1.2.2 train is embryonic:** `feat/v1.2.2-backlog` exists locally only, unpushed.
  Whichever model is kept, the version bump (→ `1.2.2+12`) must be a deliberate commit, not a
  by-product of a feature PR.

## 3. Release train — verdict: A on code/store quality, C on channels

### What is good (do not regress these)

- **Evidence-first releases:** `docs/release-evidence/v1.2.1{,-rc.2}/` (per-simulator screenshots:
  `pixel_10_pro/`, `small_phone/`), `RELEASE-GATE-v1.2.0.md`, `RELEASE-GATE-v1.2.1-rc.2.md`, and
  `test(gate): v1.2.1-rc.N` commits naming what each rc's gate verified. Four rc rounds caught
  real bugs (cursor-per-entry `7bbe237`, « Dernière : » label `4e89fb1`) — the train works as a
  bug-finding machine.
- **Store deliverable is built, not hand-written:** `store/source/en/` canonical, TranslateGemma
  prose archived under `machine/<locale>/` as proof, console character limits checked
  (`make store-check`), locale-carrying screenshot filenames — each a direct scar from the v1.2.1
  « téléchargé » incident, converted into tooling.
- **versionCode hygiene:** rc builds shared `+10` on the internal track, stable bumped to `+11`,
  the Play same-versionCode-two-tracks rule documented in the release notes.
- Tag-triggered CI → signed APK + AAB + iOS zip → idempotent GitHub release.

### Gaps

- **G1 · F-Droid** — see P1-2 (the biggest one).
- **G2 · The train itself is only implicit in commit history.** SUBMISSION-CHECKLIST.md covers

  v1.2.2 is the dress rehearsal.
